# Agentic 本地知识库搜索工具

基于 ripgrep 和大语言模型的智能文本检索系统，专为工程规范查询优化。

## ✨ 核心特性

- 🚀 **毫秒级检索**：使用 ripgrep 实现超快全文搜索，速度媲美向量数据库但无需预处理
- 🤖 **原生 Agent 架构**（V5 推荐）：基于 ReAct 范式，大模型自主调度工具，零人工规则干预
- 🗂️ **目录增强实验**（V6）：预加载总目录索引，并按需读取单文件详细目录
- 🎯 **智能目录路由**（agentic_search）：通过目录树直接定位章节，自动配对条文解释
- 💰 **极低成本**：V5 通过文件目录零成本初筛，相比 V4 打分制降低 70% Token 消耗
- 🔗 **多轮推理**：自动检测外部引用（表格、条文跳转），迭代搜索直到信息完整
- 💬 **实时反馈**：流式输出 AI 分析过程，透明展示推理路径

## 📦 快速开始

### 1. 环境要求

- Python 3.8+
- ripgrep（Windows 用户使用项目自带的 `rg.exe`）

### 2. 安装依赖

```bash
pip install openai python-dotenv
```

或使用 uv（推荐）：

```bash
uv pip install openai python-dotenv
```

### 3. 配置 API Key

复制 `.env.example` 为 `.env`，填入你的 API Key：

```env
MODELSCOPE_API_KEY=your-api-key-here
```

### 4. 准备规范文件

将文本文件（.txt 格式）放入 `specs/` 文件夹。

### 5. 运行

```bash
# V5 原生 Agent 版本（强烈推荐）
python rg_search_v5.py

# 有目录文件时使用
python agentic_search.py
```

## 🎯 版本选择指南

### 推荐版本

| 版本 | 文件 | 适用场景 | 核心优势 |
|------|------|---------|---------|
| **V5** 🚀 | `rg_search_v5.py` | 所有查询（当前默认推荐） | 原生 Agent，大模型自主调度，整体最稳 |
| **V6** 🗂️ | `rg_search_v6.py` | 已有 TOC 索引、希望辅助章节定位 | 预加载总目录 + 单文件详细目录，但目前未观察到明显收益 |
| **agentic_search** 📚 | `agentic_search.py` | 有目录结构的规范文档 | 目录路由 + 自动配对条文解释 |
| **V2** 📖 | `rg_search_v2.py` | 通用文本库，简单查询 | 无需目录，智能初筛 |

### 快速决策树

```
是否有完整目录文件（menu.json）？
├─ 是 → agentic_search（章节定位最精准）
└─ 否 → 是否想实验 TOC 预加载方案？
    ├─ 是 → V6（可试，但目前相对 V5 未显示明显优势）
    └─ 否 → 模型是否支持 Function Calling？
        ├─ 是 → V5（当前默认推荐）
        └─ 否 → V2（通用兼容）
```

## 🔧 使用方法

### V5 - 原生 Agent 版本（推荐）

**运行：**
```bash
python rg_search_v5.py
```

**自定义查询：**
```python
run_agent("钢柱的长细比要求")
```

**特点：**
- 大模型自主决定搜索策略
- 自动文件过滤（零成本）
- 自动翻页阅读上下文
- 支持多轮迭代推理

### V6 - TOC 预加载实验版本

**前提条件：** 文档可通过 `extract_toc` 生成 `index.json` 和单文件详细目录

**运行：**
```bash
python rg_search_v6.py
```

**特点：**
- 启动前自动检查并生成目录索引
- 将总目录 `index.json` 直接注入上下文
- 提供单文件详细目录工具，便于按章按节阅读
- 模型常见行为是：先搜索，再查看某本书详细目录，再精读正文
- **当前观察**：相较 V5，在精确度、响应轮数、反馈时间上暂未看出明显优势

### agentic_search - 目录增强版本

**前提条件：** 需要 `menu.json` 目录文件

**运行：**
```bash
python agentic_search.py
```

**自定义查询：**
```python
run_agentic_search("基础的宽高比")
```

**特点：**
- 通过目录树直接定位章节
- 自动配对正文和条文解释
- 精准章节切片
- 模糊文件名匹配

## ⚙️ 核心技术

### V5 / V6 的当前认识

**V5 的特点**
- 原子化工具简单：`execute_grep` + `read_file_range`
- 大模型通常能直接形成“搜索 → 阅读 → 回答”的短路径
- 整体表现目前依然最稳

**V6 的思路**
- 启动前准备好总目录 `index.json`
- 将总目录直接放入上下文
- 按需读取某个文件的详细目录 JSON，再配合正文阅读

**目前观察到的大模型行为**
- 大模型并不会稳定地优先看目录
- 常见路径是：先搜索定位相关文件，再读取该文件详细目录，再精读正文
- 这种行为和函数描述关系很大，不完全是模型天然偏好搜索

**当前结论**
- V6 的目录能力有助于缩小阅读范围、补充章节结构
- 但相较 V5，在精确度、响应轮数、反馈时间上暂未看出明显优势
- 因此当前仍优先推荐 V5，V6 更适合作为目录增强实验版本

## 📝 注意事项

1. V5 / V6 需要模型支持 Function Calling（推荐 Kimi、Qwen-Max）
2. V6 依赖 `extract_toc` 生成 `index.json` 和单文件详细目录
3. agentic_search 需要提供 `menu.json` 目录文件
4. 规范文件建议使用 UTF-8 编码
5. Windows 用户确保 `rg.exe` 在项目目录
6. API Key 需要有足够的调用额度

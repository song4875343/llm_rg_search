# 建筑规范智能检索系统

基于 ripgrep 和大语言模型的搜索本地文本的问答工具。

## 功能特点

- 🚀 使用 ripgrep 实现毫秒级规范全文检索
      只要大语言模型生成的关键词足够好，最后的成功率是大于向量搜索的。
      速度其实和向量差不多并且还不用提前生成向量。
      整体思路是把opencode 回答问题的关键部分摘出来了。
- 🧠 集成 Kimi/Qwen 大模型智能理解用户问题
- 📖 自动生成精准正则表达式，提高召回率
- 🎯 智能扩展上下文，完整呈现规范条文
- 💬 流式输出，实时展示 AI 分析结果

## 安装步骤

### 1. 环境要求

- Python 3.8+
- Windows 操作系统（请下载对应系统的rg.exe，windows系统用当前文件夹的即可）

### 2. 安装依赖

```cmd
pip install openai python-dotenv
```

或使用 uv（推荐）：

```cmd
uv pip install openai python-dotenv
```

### 3. 准备规范文件

将建筑规范文本文件（.txt 格式）放入 `specs/` 文件夹中。项目已包含以下规范：

- 建筑结构荷载规范
- 建筑抗震设计规范
- 建筑地基基础设计规范
- 混凝土结构设计规范
- 钢结构设计标准
- 砌体结构设计规范
- 高层建筑混凝土结构技术规程
- 建筑地基处理技术规范
- 建筑桩基技术规范
- 门式刚架轻型房屋钢结构技术规范

### 4. 配置 API Key

复制 `.env.example` 为 `.env`：

```cmd
copy .env.example .env
```

编辑 `.env` 文件，填入你的 API Key：

```env
MODELSCOPE_API_KEY=your-api-key-here
```

可选：修改使用的模型

```env
MODEL_NAME=moonshotai/Kimi-K2.5
```

## 使用方法

### 基本用法

直接运行脚本：

```cmd
python rg_search.py
```

### 自定义查询

修改脚本底部的参数：

```python
run_spec_query(
    user_question="什么时候需要验算竖向地震",  # 你的问题
    num_regexes=8,              # 生成正则数量（已废弃，保留兼容）
    context_lines=15,           # 上下文扩展行数
    max_matches_per_file=20     # 每个文件最多匹配数
)
```

### 参数说明

- `user_question`: 用户提出的问题（中文）
- `context_lines`: 命中行上下扩展的行数，建议 10-30
- `max_matches_per_file`: 每个规范文件最多抓取的匹配数，建议 10-20

## 程序工作原理

### 整体流程

```
用户问题 → AI 生成正则 → ripgrep 检索 → 上下文扩展 → AI 综合回答
```

### 详细步骤

1. **问题理解与正则生成**
   - 用户输入自然语言问题（如"筏板的最小厚度是多少？"）
   - 调用大模型分析问题，提取核心实体和属性
   - 生成优化的正则表达式，包含同义词扩展和规范术语转换
   - 例如：将"最小厚度"转换为 `(厚度|板厚).*(不应|不宜|不得|不小于|mm)`

2. **高速全文检索**
   - 使用 ripgrep（rg.exe）在 specs/ 目录执行正则搜索
   - 支持忽略大小写、限制匹配数等参数
   - 收集所有命中的文件路径和行号

3. **智能上下文扩展**
   - 对每个命中位置，向上下各扩展 N 行（可配置）
   - 确保获取完整的规范条文内容
   - 去重并整理成结构化片段

4. **AI 综合分析**
   - 将检索到的规范原文片段发送给大模型
   - 模型基于原文进行分析和总结
   - 流式输出答案，实时展示分析过程
   - 答案中包含规范名称、条文号和行号引用

### 核心技术

- **ripgrep**: 使用 Rust 编写的超快文本搜索工具，比传统 grep 快 10-100 倍
- **正则优化**: 通过 AI 生成的正则表达式包含同义词、规范术语等，大幅提高召回率
- **上下文窗口**: 自动扩展命中行的上下文，避免信息碎片化
- **流式输出**: 使用 OpenAI API 的 stream 模式，实现打字机效果

)

## 注意事项

1. 首次运行会自动创建 `specs/` 文件夹
2. 确保 `rg.exe` 与脚本在同一目录
3. API Key 需要有足够的调用额度
4. 规范文件建议使用 UTF-8 编码
5. 上下文行数过大会增加 token 消耗
